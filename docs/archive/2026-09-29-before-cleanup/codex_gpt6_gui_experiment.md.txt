## 论文与仓库方法

论文：[arXiv 2605.29341](https://arxiv.org/abs/2605.29341)，本地文件 `WorldMemArena_paper.pdf`。
两个 regime 是 Lifelong Evolution 和 Agentic Execution，后者含 GUI / Embodied。
三类方法范式为 long-context、manually-designed memory systems、harness-based memory agents。

仓库统一流程为 reset → 顺序 ingest session → 在 checkpoint retrieve / answer → QA 评分。

| 范式 | 仓库做法 | 本次关系 |
|---|---|---|
| Long-context | QA 时输入长历史；MMFU_Single 虽位于 memory adapters 中，也属于此类 | 未运行 |
| Engineered memory | A-Mem、SimpleMem 等用指定写入/检索模块维护记忆 | 未运行 |
| Harness-based | session 交给 harness，由其自行维护状态，checkpoint 批量答题 | 本次运行 Codex |

论文只明确顺序 session 和阶段性 QA，未规定 Codex CLI 必须 resume，亦未规定必须 fresh context。
因此 B 是研究外部记忆的一种控制协议，不能声称比作者做法更忠实。
本次消费已有 GUI 轨迹并回答 checkpoint 问题，不是启动桌面环境重新执行 GUI 操作。

## 固定协议

| 项目 | 探索 N：原生 prompt | B：fresh + memory |
|---|---|---|
| 每次调用 | 新的 ephemeral codex exec | 新的 ephemeral codex exec |
| transcript resume | 无 | 无 |
| session prompt | 原生 prompt | 明确要求读、更新、保留 memory |
| QA prompt | 原生 `_BATCH_QA_PROMPT` | 只替换信息来源为 read_memory，保留批量格式和 under 15 words 要求 |
| 工具 | shell / 文件 / view_image | 仅 read_memory / write_memory；QA 只读 |
| 跨轮状态 | 同样本专用 workspace，可自主写文件 | 单一 JSON，最大 256 KiB，结构由模型决定 |
| 截图 | 不主动附加，session 文本保留路径 | ingest 附加当前 session 截图，路径替换为 image ID |
| 旧原始轨迹和截图 | 原生工具有潜在读取能力，需审计 | 后续调用不提供；只保留模型写入的结构化/文字记忆 |

**ephemeral 不会删除 workspace 文件。** 原生 adapter 未显式传递 memory，不代表 Codex 不能自主持久化。
N 使用隔离的每样本工作目录，禁用 web、host skills/plugins，并固定 medium reasoning；所以是原生流程的受控运行，而非作者完整环境的逐字复刻。
N 的工具限制不等于 B 的 memory-only 边界；若工具访问 gold 或未来数据，须排除污染结果。
B 的 shell/view_image/web/plugins 等均关闭；审计工具事件，不把这一边界宣称为对抗性操作系统沙箱证明。

N/B 同时改变记忆机制、prompt 和显式视觉输入，**分数差不能单独归因于 memory**。
两者都不 resume；本实验不是 resume 与 fresh 的单变量比较。
两组均收到数据自带的 image caption；N 未主动附加原始截图不等于完全没有视觉描述。
运行器关闭 Codex 内置 memories feature，隔离 host 状态；N 保留自主文件读写，B 只开放指定 memory 工具。

A 是早期关闭文件工具、无显式历史传递的诊断组，不是原生主对照。已停止，保留 partial 记录：excel 33 QA，其余各 11 QA，不纳入 N/B 汇总。

- Provider：icodeeasy，`https://api.icodeeasy.cc`，Responses API。
- Backbone 和本地 judge：`gpt-6-astra`；Codex reasoning effort：medium。
- 独立运行器：`scripts/run_codex_protocols.py`；原生 `harness_native.py` 和 `harness_config.yaml` 未修改。
- 已有配置改动：`base_model_config.yaml` 增加 provider/model；`harness_api.py` 将 prompt 放在 greedy `--image` 参数前，修复 CLI 解析，不改变 prompt 内容。本次 N/B 使用独立运行器。
- MCP：`scripts/wma_memory_server.py`；只操作固定 memory 文件，原子写入；QA 暴露只读工具。
- 传输：`scripts/wma_transport.py`，本机随机 localhost 端口转发相同 Responses JSON / SSE 到上述 provider，不换模型或工具循环。日志不记录认证头。
- 汇总：`scripts/summarize_codex_protocols.py`。
- 审计：`scripts/audit_codex_protocols.py`。六组共 180 次调用、322 QA 已通过核验：180 个独立 thread；N 没有工具调用，B 仅使用记忆工具；题目、gold 和答案与对应数据及调用记录一致。

CLI 直连曾反复 Connection failed，而 Python HTTPS 请求正常；本地转发解决该兼容问题。
MCP 必须配置 server-scoped `default_tools_approval_mode = "approve"`；早期 auto 导致写入被阻止，相应失败实验排除。
单调用超时 900 秒，每次运行至多重试 3 次；失败记录保留，B 重试前恢复上轮 memory。
空响应、零 input tokens、无 memory 写入、非法工具或无效 judge 不接受为成功。
续跑按 prompt/图片/protocol/model hash 复用完成调用，并恢复 memory 快照。
